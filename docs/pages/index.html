IoT Distributed Event Platform

Event-driven IoT system built on MQTT. A simulated sensor publishes temperature readings; a central consumer subscribes and processes them, with differentiated QoS levels per channel.

Broker Connection Info

Hostname, port, transport, and TLS settings for connecting any MQTT client to the live broker.

Connect to the live broker

The broker speaks MQTT over WebSocket with TLS. Any MQTT client that supports this transport can connect using the following settings:

Setting Value
Host iot-emqx-broker.onrender.com
Port 443
Transport websockets
TLS Enabled (terminated at the edge)
WebSocket path /mqtt
Authentication None

Subscribe to the demo stream

A low-frequency publisher (demo-publisher-001) emits one reading every 30 seconds to keep the free-tier broker awake. Use mosquitto_sub to observe the stream: 

mosquitto_sub \
    -h iot-emqx-broker.onrender.com \
    -p 443 \
    --ws-path /mqtt \
    -t 'iot/sensors/demo-publisher-001/#' \
    -v

Or with the Python client included in this project:

git clone https://github.com/JalaU-Labs/iot-distributed-event-broker
cd iot-distributed-event-broker
uv sync
MQTT_BROKER_HOST=iot-emqx-broker.onrender.com \
MQTT_BROKER_PORT=443 \
MQTT_TRANSPORT=websockets \
MQTT_USE_TLS=true \
MQTT_WS_PATH=/mqtt \
uv run iot-consumer

Usage notes

Best-effort service. The broker runs on Render's free tier. It sleeps after 15 minutes of inactivity and cold-starts in approximately 30 seconds. There is no SLA, no authentication, and no message persistence. Topics are shared by all users of this instance. Please use it for evaluation and learning purposes only.
